# 商品图片存储策略

## 开发环境

商品图片写入 Git 已忽略的 `backend/var/public-products/`。新上传内容先进入 `temporary/<用户>/<上传>/`，只通过带身份验证的预览接口读取；商品保存确认后才移动到随机命名的永久对象键。不得把该目录加入 Git。

系统只接受真实内容为 JPEG、PNG 或 WebP 的文件，同时校验扩展名、声明 MIME、字节数和解码后像素数。服务会重新编码图片、移除 EXIF，并生成 WebP 缩略图。SVG、损坏图片和路径穿越对象键均会被拒绝。

临时记录默认保留 24 小时。定时运行 `python -m app.db.cleanup_product_images`，只清理数据库中仍为 `temporary` 且超过过期时间的对象。商品和图片使用软删除与后续保留期清理，不立即删除已确认对象。

## 生产环境

生产环境应使用私有 S3 兼容桶和 `S3CompatibleObjectStorage` 适配器。临时原图保持私有；公开商品只通过受控 API 或经过授权的派生图地址访问。桶凭据、端点与签名配置必须由运行环境注入，不写入仓库、日志或前端变量。

数据库事务是归属事实源：上传对象创建失败会立即补偿删除；事务回滚执行注册的删除回调；商品确认流程应先锁定临时记录并更新归属，再在提交后完成对象移动。清理任务必须使用 `temporary` 状态与安全时间窗口，不能只按目录时间删除文件。
