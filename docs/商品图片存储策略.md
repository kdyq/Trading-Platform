# 商品图片存储策略

## 开发环境

商品图片写入 Git 已忽略的 `backend/var/public-products/`。新上传内容使用 `temporary/<用户>/<上传>/` 形式的随机对象键，只通过带身份验证的预览接口读取；商品保存时由数据库事务原子确认归属，对象键保持不变。不得把该目录加入 Git。

系统只接受真实内容为 JPEG、PNG 或 WebP 的文件，同时校验扩展名、声明 MIME、字节数和解码后像素数。服务会重新编码图片、移除 EXIF，并生成 WebP 缩略图。SVG、损坏图片和路径穿越对象键均会被拒绝。

临时记录默认保留 24 小时。定时运行 `python -m app.db.cleanup_product_images`，只清理数据库中仍为 `temporary` 且超过过期时间的对象。商品和图片使用软删除与后续保留期清理，不立即删除已确认对象。

## 生产环境

当前运行依赖使用本地文件存储；`S3CompatibleObjectStorage` 适配器尚未接入应用配置。生产环境可选择经过备份管理的本地卷，或在完成适配器注入、配置和实际读写验收后使用私有 S3 兼容桶。临时原图保持私有；公开商品只通过受控 API 或经过授权的派生图地址访问。桶凭据、端点与签名配置必须由运行环境注入，不写入仓库、日志或前端变量。

数据库事务是归属事实源：上传对象创建失败会立即补偿删除；事务回滚执行注册的删除回调；商品确认流程锁定临时记录，并在同一事务内让商品图片引用原随机对象键、将上传记录改为 `confirmed`。确认时不跨提交边界移动对象，避免确认移动与数据库提交之间的不一致窗口。初次上传在文件写入后、数据库记录提交前发生进程硬中断，仍可能留下无记录对象；定期对照引用审计，经安全时间窗口及人工复核后清理。常规清理任务只使用数据库 `temporary` 状态与过期时间，不能按目录时间直接删除文件。
