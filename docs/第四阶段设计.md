# 第四阶段设计系统与公共市场设计

## 1. 设计读取与范围

本阶段是对现有“拾光集市”品牌的保留式扩展，服务对象是希望快速浏览、判断可信度并发起校内交易的学生。视觉保持暖纸张背景、白色摊位卡片、汽水橙关键操作和信任绿安全语义，继续使用 Vue、原生 CSS 与现有 GSAP。

设计参数为 `DESIGN_VARIANCE 7 / MOTION_INTENSITY 5 / VISUAL_DENSITY 5`。页面允许有市集感的不对称构图和克制动效，但移动端必须回落到稳定单列，任何内容都不能依赖动画才可见。

本阶段允许新增首页、搜索和详情所需的只读公共商品 API。商品发布、图片上传、收藏持久化、下单写入和完整 PostgreSQL 搜索仍属于第五阶段及以后，不在本阶段提前实现。

## 2. 方案选择

采用“共享设计基元 + 最小只读市场 API + 路由级页面组合”。共享基元统一颜色、间距、圆角、状态和无障碍合同；只读 API 从既有 PostgreSQL 模型查询公开商品；首页、列表和详情页按各自职责组合基元。

未采用纯静态演示方案，因为它无法满足真实接口、失败态和商品状态验收。未采用一次性首页大组件方案，因为其状态、动效和响应式难以独立测试，也不利于四个任务分别提交和回滚。

## 3. 组件与样式边界

- `UiButton`：主按钮、描边按钮和危险/禁用状态，原生按钮与链接保持同一视觉合同。
- `UiField`：标签、帮助文本和字段错误，标签始终在控件上方。
- `UiChip`：筛选、状态和只读徽章；筛选选中态为墨棕底白字。
- `ProductCard`：统一承载图片、标题、价格、校区、学院、发布时间、成色与商品状态。
- `UiDialog`：模态焦点进入、Tab 循环、Escape 关闭和焦点恢复。
- `UiToast`：短暂反馈的 `aria-live` 容器，不替代页面级错误。
- `UiSkeleton`：按最终内容比例占位，减少布局偏移。

语义令牌集中在 `styles/tokens.css`，布局和组件规则集中在 `styles/base.css`。卡片使用 16px 圆角，输入使用 12px 圆角，按钮、徽章和筛选使用胶囊圆角。阴影只使用低透明暖棕色。

## 4. 只读公共市场 API

新增 `/api/v1/market/categories`、`/api/v1/market/products`、`/api/v1/market/products/{id}` 与 `/api/v1/market/summary`。接口只返回未删除且允许公开的商品，不暴露审核原因、私有校园邮箱、卖家登录邮箱或内部存储键。

列表接口支持关键词、分类、校区、最低价、最高价、成色、可议价、状态、排序和分页。第四阶段使用结构化 SQL 条件、稳定排序和请求取消合同，不引入搜索引擎。若现有数据模型缺少成色、可议价或浏览统计字段，本阶段通过向后兼容迁移补齐只读展示所需字段，但不实现发布写入流程。

隐藏、删除、草稿和拒绝商品对游客统一按不存在处理。审核中商品只允许通过明确的状态演示或本人未来入口展示，公共列表不返回。已售商品可在详情或卡片中展示，但操作禁用。

## 5. 页面与数据流

首页加载分类、摘要和最新公开商品。真实统计为空时显示诚实文案，不制造成交数字。分类入口和首页筛选均跳转到 `/market` 并写入 URL 查询参数。

市场列表以 URL 为唯一筛选真源。桌面显示侧栏，移动端使用底部模态筛选；两者编辑同一份草稿，应用后一次性更新 URL。关键词输入防抖，后续请求会取消前一请求；刷新、前进后退和分享链接均可恢复状态。

详情页按路由 ID 读取单个商品，展示 4:3 画廊、卖家可信信息、描述和相似商品。游客点击收藏、联系或发起交易时显示登录门禁；已登录但未校园认证时进入校园认证门禁；本人商品、已售商品和不可公开商品按状态禁用。

## 6. 动效与响应式

首页首屏使用一个带标签的 GSAP 时间线建立信息层级；悬浮商品卡、认证印章、计数和单条跑马灯分别服务于市集氛围、可信语义和信息反馈。桌面页面长廊使用 `ScrollTrigger` 固定外层并以 `ease: none` 横移内层；768px 以下改为原生横向滚动。

所有 GSAP 动画在 `onMounted` 后、组件根节点作用域内创建，并在 `onUnmounted` 时通过 context 或 matchMedia 回滚。只动画 transform 与 opacity。`prefers-reduced-motion` 下不创建循环、计数、跑马灯或固定横移，内容保持静态可见。

容器最大宽度 1180px，桌面保留 24px 横向安全边距，移动端保留 16px。375、768、1024、1440 四档均不得出现页面级横向滚动。

## 7. 错误、空态与访问控制

每个请求都具有加载、空数据、失败和成功状态。列表错误保留当前筛选并允许重试；详情 404 与暂时失败使用不同界面；图片加载失败回落到固定比例的文字占位，不暴露对象键。

公共浏览不要求登录。收藏、联系和交易入口只实现清晰门禁与下一步导航，不在本阶段伪造成功或持久化。前端不能仅通过视觉禁用保护动作，后续真实写接口仍必须执行服务端授权。

## 8. 测试与提交顺序

1. 设计令牌、七类组件、四种商品卡状态、组件演示和无障碍基础测试，形成任务 1 提交。
2. 只读首页数据、首页布局和首页动效，形成任务 2 提交。
3. URL 筛选、并发取消、分页和移动筛选焦点管理，形成任务 3 提交。
4. 商品详情、画廊、可信信息、门禁、SEO 和相似商品，形成任务 4 提交。
5. 运行后端静态检查与测试、PostgreSQL 门禁、前端类型/Lint/格式/单测/构建，并在四档视口执行真实浏览器验收和截图对照。

## 9. 自审结论

- 没有 `TBD`、`TODO` 或依赖用户后续选择的占位要求。
- 只读 API 与第五阶段写入边界明确，不提前实现发布、收藏或订单。
- 组件、页面、数据流、错误态、动效清理和验收顺序彼此一致。
- 所有新增能力均可归入第四阶段四个任务，适合逐任务提交和失败回滚。
