# 监控与安全运维

本文是待接入方案，尚未创建真实监控或告警资源。试运行前确认采集平台、保存位置、通知渠道、技术值班与安全负责人。

## 观测范围与初始告警

阈值是初始思路，应按真实流量基线校准。连续窗口、最小请求量和恢复窗口用于控制误报；每条告警都要验证通知到达及人工响应。

| 信号 | 初始触发思路 | 级别 | 响应与误报控制 |
| --- | --- | --- | --- |
| API 可用性 | `/live` 或 `/ready` 连续 3 次失败 | P1 | 核对数据库/Redis/进程；维护窗口静默，保留失败原因 |
| API 错误率 | 5 分钟 5xx 超过 2%，且请求数至少 100 | P1 | 查请求 ID 和部署变更；按路由分组，排除预期 4xx |
| 延迟 | 10 分钟 P95 超过经确认的体验目标 | P2，关键交易升级 P1 | 检查连接池、SQL、CPU/内存；小流量同时看样本量 |
| PostgreSQL | 连接使用超过预算 80%、持续锁等待或备份失败 | P1/P2 | 查阻塞会话与慢查询，限制入口；不直接结束未知事务 |
| Redis | 认证计数/票据服务不可用或持续广播重连 | P1 | 暂停受影响入口，检查认证失败关闭；核心事实不靠 Redis 恢复 |
| 存储 | 可用空间低于 20%、对象读取/写入失败 | P1/P2 | 暂停上传，核对权限、配额和引用，禁止删未确认业务文件 |
| 邮件 | 连续投递失败、积压超过服务目标 | P2 | 暂停验证码入口或提示重试，核对邮件服务；不记录验证码 |
| WebSocket | 断连率、重连次数或补拉延迟持续偏离基线 | P2 | 检查代理、Redis和会话；按客户端/版本聚合，排除主动退出 |
| 审核/申诉 | 最老待处理项超过约定时限或积压持续增长 | P2 | 扩充值班/缩小开放范围；同时看工作时段和待处理数量 |
| 滥用 | 注册、上传、聊天、举报限流命中突增 | P2，批量越权升级 P0 | 查非敏感聚合与账号状态；同一网络不能直接视为恶意个人 |

## 日志与隐私

现有结构化日志保留时间、请求 ID、路由、方法、状态码和耗时。代理生成或传递受控请求 ID，跨服务记录该 ID；不要通过用户输入伪造可信身份。采集系统不得记录密码、SMTP 授权码、验证码、Cookie、Bearer/刷新令牌、私聊正文、完整邮件地址或认证材料。错误追踪关闭请求体、敏感头与用户文本，按路由和异常类型聚合。

日志、审计与业务数据的用途和访问权分离，保存期由组织方确认并配置轮换、到期删除和审计。运维访问遵循最小权限，不能从日志直接恢复用户隐私内容；安全调查使用经授权的业务接口和证据流程。

## 维护与事件处理

1. 密钥轮换：清点认证、验证码、数据库、Redis、SMTP及存储凭据；先验证新凭据，再安排切换。当前认证不具备无感双密钥轮换，切换认证密钥需计划用户重新登录及会话撤销。
2. 系统更新：在预发布验证 OS/依赖/数据库补丁和迁移兼容，保存旧版本与一致备份；逐项发布，不能同时升级全部基础设施。
3. 漏洞响应：确认影响与利用条件，暂停受影响功能、保全请求 ID/时间、撤销被泄漏凭据；修复和回归后由负责人确认恢复，不公开私密证据。
4. 管理员离职：超级管理员停用后台账号或回收角色，验证会话撤销和权限拒绝、保存审计，并检查其外部平台/密钥权限。最后有效超级管理员不得被停用或移除。
5. P0 数据泄漏或批量越权立即收紧入口并升级安全负责人；P1 关键链路故障当班处理；P2 局部问题进入修复队列。记录主责、替补、时间线、恢复证据和用户通知授权。

## 探测与回退模板

以下模板仅供未来部署后执行，不在本阶段创建资源。

```text
curl --fail https://<site-domain>/api/v1/health/live
curl --fail https://<site-domain>/api/v1/health/ready
<metrics-tool> query <approved-non-sensitive-metric>
```

监控配置失败时保留已有受控日志及人工巡检，限制试运行规模；通知渠道失效时使用预先登记的替补渠道。部署或指标异常按[发布流程](发布流程.md)回到兼容版本，数据问题按[运维手册](运维手册.md)在隔离环境恢复。
