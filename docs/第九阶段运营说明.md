# 第九阶段本地运营说明

后台 API 与审计导出 worker 是两个独立进程。先完成数据库迁移和角色权限种子，再启动 API 与常驻 worker；仅启动 API 会使导出停留在 `queued`。以下命令在仓库的 `backend` 目录执行，使用项目指定的 Python 环境，并要求当前进程已有正确的 `DATABASE_URL` 等配置，不在命令或文档中填写真实凭据。

```powershell
& D:\python\virtual\fastapi-env\Scripts\python.exe -m alembic -c alembic.ini upgrade head
& D:\python\virtual\fastapi-env\Scripts\python.exe -m app.db.seed
& D:\python\virtual\fastapi-env\Scripts\python.exe -m app.workers.audit_export
```

worker 命令需在单独终端或受进程管理器守护下持续运行；默认每 5 秒查询队列，可用 `--interval 10` 调整。`--once` 仅用于一次性处理当前队列、检查或演练，不用于持续试运行。worker 异常时会继续轮询，已领取但中断的任务在最后心跳超过 10 分钟后标记为 `failed`，不会被其他 worker 直接抢写同一文件；操作者可重新发起任务。任务一小时后过期，撤销或过期文件由 worker 清理。导出目录位于私有存储根目录的 `exports/`，不得当作公开静态资源挂载；API 下载仍重新检查权限、所有者、期限和撤销状态。

首次超级管理员账号只能由操作员在 `backend` 目录显式运行 `python -m app.db.bootstrap_super_admin` 创建，不随 API 启动自动生成。该账号用户名固定为 `guo`，没有登录邮箱，也不写入虚构的校园邮箱或校区记录；`SUPER_ADMIN` 角色使其账户展示认证状态为 `verified`，校园认证人数指标仍只统计真实认证记录。这表示管理员免校验，不等于真实校园身份；商品发布和订单等校园交易能力仍需真实校园认证。初始密码通过无回显提示输入，或仅在当前进程临时设置 `BOOTSTRAP_SUPER_ADMIN_PASSWORD`；不要把密码写进命令行、脚本、日志或仓库。用户名已存在时命令拒绝覆盖。首次登录后必须先修改密码才能执行后台或业务操作。无邮箱账号无法通过邮件找回密码，应妥善保管改密后的凭据。

本地 `backend/.env` 与 `.codex/config.toml` 的数据库身份配置可能不一致；若迁移或 worker 连接失败，应核对当前进程实际加载的非秘密连接参数和账号权限，不要覆盖现有 `.env` 或在诊断输出中打印完整连接串。正式试运行前，应把 API、worker 与私有存储纳入同一进程管理/备份方案，并确认最小权限数据库账号与访问日志保留策略。
