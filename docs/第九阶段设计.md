# 第九阶段管理后台、RBAC 与运营能力设计

## 范围与验收

仅完成开发文档第九阶段四项任务。所有后台 API 在后端以当前数据库角色/权限授权；角色变更和停用立即撤销目标会话。高风险写操作要求近期登录、明确理由、目标确认与追加式审计。列表必须服务端筛选、分页和稳定排序；敏感字段按权限裁剪。仪表盘指标给出 SQL 可复核口径和时间窗口；审计只读，导出由独立任务处理、短期有效并可撤销。

## 方案比较与选择

方案 A 是只在前端按角色隐藏菜单、后端维持分散角色字符串判断。它改动小但无法表达客服与细粒度权限，也无法阻止直接调用 API。方案 B 是使用现有 `roles`、`permissions`、关联表持久化固定权限矩阵，后台命令先检查会话、强制改密标志、权限，再在单事务内执行状态变更与审计。它复用既有模型且能独立测试权限矩阵，选用此方案。方案 C 是全面可配置角色设计器与策略引擎，容易让普通管理员形成权限提升路径，超出试运行需要，不采用。

角色代码固定为 `USER`、`SUPPORT`、`REVIEWER`、`ADMIN`、`SUPER_ADMIN`。权限矩阵由幂等种子维护：普通用户无后台权限；客服只读脱敏用户/商品；审核员有商品、举报与校园认证审核；管理员有运营数据、用户状态、商品状态、分类校区维护；超级管理员拥有所有权限以及后台人员管理和审计导出。授权取角色并集，但 `SUPER_ADMIN` 的授予/移除与最后一名有效超级管理员保护只能由超级管理员执行；高风险操作另外检查近期登录和目标确认。保留第八阶段审核 API 的兼容行为，但改为同一权限来源。

## 任务 1：账号初始化与强制改密

用户表有唯一可空 `username` 和 `must_change_password`；修正后的迁移允许登录邮箱及其验证时间为 `NULL`，但数据库要求邮箱或用户名至少存在一个。普通注册仍必须提供邮箱，既有邮箱登录不变，登录输入允许邮箱或用户名。一次性命令固定创建用户名 `guo`、不设置登录邮箱，密码从无回显交互输入或临时环境变量读取，代码与日志不保存明文；已有用户名即拒绝覆盖/重置。具备 `SUPER_ADMIN` 角色的账号，其账户展示与登录响应中的认证状态由角色计算为 `verified`，无需邮箱或伪造校园认证记录；失去该角色即失去此特例，校园认证人数指标仍只统计真实校园认证事实。这是平台管理员免校验状态，不是校园身份事实；商品发布、订单等校园交易能力仍须检查真实校园认证记录。初始口令仅能登录、查看本人信息和修改密码；任何后台或业务 API 均在改密前拒绝。改密后撤销其他会话。无邮箱账号不能使用邮件找回密码，需使用当前密码修改或经过另行授权的恢复流程。实际初始化应在迁移、门禁和安全审查完成后显式执行，并读取确认用户名、角色、空邮箱与有效认证状态。

## 任务 2：后台人员与角色

管理员列表仅返回必要字段和角色，邀请已有邮箱账号进入后台：若邮箱不存在，先走正常注册/验证流程，避免无验证的后台身份。角色分配只接受固定角色集合，超级管理员不可给自己扩大权限，普通管理员无人员管理权限。停用/启用、角色变更需原因、确认目标和近期登录；操作者、前后角色/状态、理由、时间记入现有不可变 `audit_logs`，目标现有会话全部撤销。并发变更锁定目标用户与超级管理员集合，保护最后一位有效超级管理员。

## 任务 3：日常运营管理

用户与商品检索采用数据库分页与 `(created_at DESC, id DESC)` 稳定排序；角色不同只返回授权字段，邮箱脱敏，校园认证材料只供审核权限访问。用户停用、商品隐藏/恢复复用现有状态机和审计边界，不硬删除订单与证据。分类与校区沿用现有管理 API，补充同一权限种子与后台页面。校园认证复核沿用既有申诉模型与私有下载，要求审核权限及理由；不把私有材料混入通用列表。

## 任务 4：指标、审计与导出

仪表盘只做确定性 SQL 聚合，时间区间以 UTC 起止半开区间表示：新增注册、认证成功、上架、成交、待审、举报与未撤销且未过期的会话。审计搜索按时间、动作、操作者、目标筛选，白名单字段脱敏后返回，只读不提供更新/删除。导出创建时记录操作者、筛选条件、期限和状态，独立 worker 分页输出带操作者/时间水印的 CSV；下载重新检查当前权限、所有权、过期与撤销状态，文件存储于私有目录。失败保留任务状态而不泄露内部栈。

## 自审、实施与门禁

设计自审：不修改第八阶段证据/信用历史；不会把前端菜单当授权边界；不会因管理员停用丢失用户与订单事实；初始化必须是显式一次性操作，不能随应用启动自动执行。风险集中于会话撤销、并发最后超级管理员、认证材料与导出访问，需 PostgreSQL 集成测试和只读深入审查。

按任务 1–4 分别实现、跑对应测试并独立提交。最后运行 `scripts/check.ps1 -Postgres` 和后台浏览器 E2E，检查 Git 差异中无明文凭据；按 `requesting-code-review` 及项目 AGENTS.md 使用 `reviewer_deep` 做独立只读审查，修复重要问题后复跑门禁。本阶段完成后停止，不进入第十阶段。
