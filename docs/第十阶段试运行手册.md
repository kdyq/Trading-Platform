# 拾光集市校内试运行手册（第十阶段草稿）

## 启动条件与责任

范围限单校、受邀账号、小规模线下交易；不在本阶段自动开启真实试运行或部署。启动前由组织方填写真实负责人、替补、联系方式、试运行日期、预计账号数、备份位置与保留期限，并核对隐私说明、学校规则和服务入口。角色占位为「技术值班」「校园运营」「安全/隐私负责人」；每角色需有一名主责和一名替补。没有人员与通知渠道时保持注册关闭，不进入真实试运行。

试运行目标：RPO 不超过 24 小时、RTO 不超过 4 小时。这是待组织方落实的目标，不是当前单机系统已达到的保证。应至少每日完成一次 PostgreSQL 自定义格式备份和同一时间点的私有/公开对象文件快照，将备份加密保存到独立位置，并每周在隔离环境恢复核验。数据库和对象快照必须使用同一冻结窗口：停止所有 API 实例、上传入口、审计导出与清理 worker、订单过期和通知后台任务，以及任何其他会写入数据库或增删对象文件的进程；等待进行中的请求退出并确认无写入者后，依次生成 `pg_dump` 与对象快照，在两个备份及哈希完成前保持冻结。恢复后逐条核对原图、缩略图及私有对象键。单靠关闭注册/发布/交易开关不能形成一致快照。未建立定时、加密、异地与告警前，不能宣称达到 RPO/RTO。

## 发布前门禁

1. 检查 Git 版本、`.env` 中功能开关、数据库迁移版本、对象存储根目录、Redis、API 和 `app.workers.audit_export` 常驻进程。不要在日志或工单粘贴密码、完整连接串、验证码和用户材料。
2. 在项目根目录执行 `scripts/check.ps1 -Postgres`，保存退出码与摘要；再进入 `backend` 目录执行 `python -m scripts.performance_stage10 --output ../docs/第十阶段性能数据.json` 复核本机阈值。
3. 使用隔离账号运行真实浏览器旅程，复核 375/768/1024/1440 宽度、正常和减少动态效果模式、控制台与网络。保留截图与异常清单。
4. 在 `backend` 目录以隔离数据执行 `python -m scripts.recovery_drill_stage10 --output ../docs/第十阶段恢复演练数据.json`。记录迁移版本、核心数量、原图/缩略图引用和耗时。每次正式备份方案变更后重复演练。

## 功能暂停与应急处置

修改环境变量并重启 API（含所有实例），不删数据：`AUTH_REGISTRATION_ENABLED=false` 暂停注册，`PUBLISHING_ENABLED=false` 暂停新建商品草稿、提交审核、审核通过和管理员直接恢复上架，`TRADING_ENABLED=false` 暂停新建订单。发布开关不阻止隐藏、撤回或处理现有申诉；申诉成立时撤销处罚，但原先在售的隐藏商品保持隐藏，待恢复发布后由有权限的审核员重新确认上架。交易开关不阻止取消、完成或处理既有订单。开关默认开启，试运行启动前应按批准范围显式设置。验证暂停时分别返回稳定代码 `registration_closed`、`publishing_paused`、`trading_paused`；恢复需经技术值班和校园运营确认并记录时间。

管理员应急停用用户和内容下架通过既有后台高风险操作，需重新认证、目标确认和审计；举报/申诉继续处理。若发现权限泄漏、疑似凭据暴露或大面积错误，立即暂停三项入口、限制外部入口、保存请求 ID 和时间范围，技术值班升级给安全/隐私负责人。后台审计导出仅在授权范围内生成，文件到期后由 worker 删除；不要用公开文件服务分享导出。

## PostgreSQL 与对象恢复

正式备份由技术值班在独立备份目录执行 `pg_dump --format=custom --file <绝对路径> --dbname <数据库名>`，连接参数通过受控环境变量或本机凭据文件提供，不写进命令行、仓库和报告。记录备份开始/结束时间、文件哈希、迁移版本、用户/商品/图片/订单数量；对象快照包括公开商品图和私有申诉/举报材料、审计导出目录。Redis 的验证码、一次性 WebSocket 票据与限流计数属于短期非持久事实，恢复后让其重新生成，不回放旧票据；会话与业务状态以 PostgreSQL 为准。

发生故障时先暂停写入并保全原库及文件，再在**新隔离数据库或 schema** 用 `pg_restore --no-owner --no-privileges --dbname <隔离数据库名> <备份文件>` 和配套对象快照恢复。核对 `alembic_version`、核心表数量、随机抽样订单及全部图片引用文件存在性与哈希；完成授权、登录、商品浏览、订单和后台只读烟测后，按事故负责人批准的切换步骤恢复服务。应用回滚先核对旧版本与当前迁移兼容性；不对含真实数据的库直接执行 `alembic downgrade`。若不兼容，优先修复前进或从事故前一致快照整体恢复，并记录可能的数据损失窗口。

本次隔离演练以 `test_gate_*` schema、1 名测试用户、1 件商品、独立的原图和缩略图文件、8 个分类完成：备份 3.69 秒、恢复 0.54 秒；恢复前后迁移版本 `4c8d27a1e903`、各表数量及两个对象的 SHA-256 一致。原始证据见 `第十阶段恢复演练数据.json`。该小样本耗时不代表真实 RTO，也未证明独立设备故障时的可用性。

## 反馈、分级与退出

校园运营每日汇总反馈并标记请求 ID、时间、页面、角色、复现步骤和影响范围，不收集密码或私聊全文。P0（数据泄漏/批量越权/数据不可恢复）立即暂停入口并升级；P1（交易关键链路阻断）在当班内升级并考虑暂停交易；P2（局部功能或体验）进入修复队列。每次恢复或重新放开功能开关都记录操作者、审阅者、时间、验证结果。

退出试运行条件：出现未解决 P0、无法恢复一致备份、真实数据保存要求未落实、关键旅程持续失败，或值班/反馈责任缺位。进入扩大试运行前，应复核门禁记录、实际 RPO/RTO 演练、用户反馈、已知问题和组织方签署的隐私文本；第十一阶段仍只做部署方案设计。
