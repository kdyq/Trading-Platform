# 拾光集市账户规则

本文描述当前账户注册、登录与校园认证规则。普通账户与校园认证是两条独立链路，注册成功不代表已完成校园认证。

## 1. 注册资料

普通用户注册时只要求以下资料：

1. 登录邮箱；
2. 公开昵称；
3. 密码；
4. 分别同意当前版本的《用户协议》和《隐私政策》。

注册阶段不收集学校、校区、学号、校园邮箱或认证材料。登录邮箱可以是普通邮箱，不得被自动当作校园认证邮箱。

## 2. 登录邮箱

- 登录邮箱是普通账户的登录标识，不公开展示。工作人员账号也可使用用户名登录；初始化超级管理员 `guo` 仅使用用户名。
- 保存和比较前去除首尾空白并转换为小写。
- 同一登录邮箱只能注册一个未删除账户。
- 创建账户前必须完成该登录邮箱的验证码校验。
- 验证码邮件由 QQ 邮箱 SMTP 服务发送。邮箱账号和授权码只写入 Git 忽略的 `backend/.env`，仓库中的示例配置只保留非敏感占位符。

## 3. 公开昵称

- 普通注册不要求用户名，账户使用公开昵称展示身份。工作人员用户名与公开昵称分开保存。
- 昵称长度为 2-30 个 Unicode 字符，去除首尾空白。
- 昵称允许重复，不作为登录凭据或唯一身份标识。
- 昵称不得包含控制字符，也不得冒充平台官方身份。

## 4. 密码

- 长度为 8-128 个字符。
- 至少包含一个英文字母和一个数字。
- 不允许包含空格或其他空白字符。
- 拒绝常见弱密码，以及与登录邮箱高度相似的密码。
- 服务端只保存成熟密码哈希算法产生的摘要，不保存或记录明文密码。

## 5. 协议与隐私政策

- 《用户协议》和《隐私政策》必须分别明确勾选，不得使用默认勾选。
- 服务端记录用户同意的文档版本与同意时间，以便后续审计。
- 法律文本内容及正式版本号由项目方另行提供；开发环境可通过非敏感配置指定版本标识，但不得虚构正式条款。

## 6. 注册开放范围

- 默认开放普通账户注册，不要求邀请码。
- 保留全局注册开关；关闭时新注册请求返回稳定的业务错误，既有用户仍可登录。
- 当前没有邀请码能力，若启用需先确定规则和数据模型。

## 7. 校园认证边界

- 校园邮箱只用于独立的校园认证流程，不替代登录邮箱。
- 用户可先注册和登录，再选择学校、校区并提交校园认证。
- 校园认证通过前可浏览；已登录用户还可收藏、管理本人账户、举报与申诉。发布、私聊、下单和评价由统一校园身份门禁拒绝。
- 学校、校区、邮箱域名及认证有效期必须来自可配置数据，不在代码或文档中虚构具体学校资料。

## 8. 管理员与暂停账户

初始化管理员必须在首次登录后修改密码。管理员管理权限不等于真实校园身份，校园交易仍需有效认证。暂停账户保留本人账户安全、通知与处罚申诉入口，不能继续交易或访问后台；工作人员停用通过专门权限流程处理。账户规则改变时应同步更新本文与隐私文本。
