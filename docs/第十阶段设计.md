# 第十阶段设计：安全、性能与校内试运行门禁

## 范围和验收口径

本阶段只处理单校、小范围试运行前的安全、性能、可恢复性和发布检查，不启动真实试运行，也不执行第十一阶段的部署。每项任务独立检查并提交。所有压测与恢复演练使用隔离的测试 schema、测试账号和非生产对象文件；真实用户数据不得复制到报告或备份样本。

## 任务 1：应用安全与隐私

以现有 Bearer 访问令牌、HttpOnly 刷新 Cookie、PostgreSQL 对象授权和 Redis 计数为基础加固。入口按 IP 与路由分层限流，登录另按账号标识计数；验证码、聊天和举报保留现有主体限流。生产环境对认证入口的 Redis 故障关闭请求，其他入口可用有界本地兜底并记录降级。只信任直连客户端 IP，不从未经校验的转发头取地址。刷新 Cookie 的跨站写入继续校验 Origin，WebSocket 同样校验 Origin 和一次性票据。应用加安全响应头；前端只用 Vue 文本插值，不渲染用户 HTML。

隐私数据分为公开商品信息、账号联系方式、校园认证材料与举报证据、会话内容及审计记录。公开接口只返回必要字段；私有文件通过授权接口提供。新增隐私说明，写明实际收集、用途、当前保存与删除机制，不推定法定期限。账号注销先处理未完结交易和治理事项，再撤销会话、禁用账号与去标识；需要保留的交易/审计记录按运营规则处理，不执行跨表硬删除。以安全测试、反向越权与注入测试、静态检查为门禁。

## 任务 2：性能

报告记录机器、版本、数据库样本量、并发、请求组合、P50/P95、错误率、连接数和资源占用。测试场景覆盖首页、搜索、详情、聊天历史、下单和后台队列；受写入影响的请求使用独立测试数据。先查看 SQL 与 `EXPLAIN (ANALYZE, BUFFERS)`，只针对观察到的慢点改索引或查询。权限结果与私密消息正文不缓存，Redis 故障时核心事实以 PostgreSQL 为准。若本机数据量不足以证明生产容量，报告明确这个限制，不外推到真实校内负载。

## 任务 3：自动化和浏览器

统一运行 `scripts/check.ps1 -Postgres`，再使用隔离浏览器账号跑角色旅程。保存命令、版本、退出码和截图路径；对 375、768、1024、1440 宽度的生产预览检查页面溢出、控制台、请求失败及 reduced-motion。状态机的成功、失败、幂等、并发与越权由单测和 PostgreSQL 集成测试共同覆盖。测试数据在隔离 schema 中创建与清理，浏览器脚本需能独立重跑。

## 任务 4：恢复和试运行

提供功能开关暂停注册、发布、交易，暂停时返回稳定业务错误，不删除已有数据。操作手册描述 PostgreSQL 备份恢复、对象文件快照一致性、Redis 非持久数据重建、管理员停用/下架/导出、应用版本回滚和验证步骤。恢复演练在新隔离库或 schema 上完成，核对迁移版本、核心计数与对象引用；记录实际 RPO/RTO 测量值，与试运行目标区分。值班责任以角色占位，真实责任人、时间和外部平台在启动试运行前填定。

## 自审

上述选择沿用现有项目接口和本地依赖，不引入外部服务。安全限流不能替代代理层防护；单机压测不能证明多实例或真实校内峰值。若外部依赖或非生产数据条件不足，门禁保持未通过并记录证据，不能把文档视为演练完成。
