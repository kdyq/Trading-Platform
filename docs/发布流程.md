# 构建、迁移与发布流程

本文仅为发布设计，没有执行生产发布或镜像推送。所有命令中的尖括号项必须在未来发布前替换，并经负责人确认。

## 发布前准备

固定 Git 提交、Python 依赖版本和 pnpm 锁文件，记录变更、兼容范围、配置差异、迁移目标、回滚版本及验证人。构建产物与运行密钥分离；不得将 `.env`、私有文件、数据库备份或凭据打包进镜像。后端依赖在隔离构建环境安装，前端使用锁定依赖。

```text
git checkout <approved-commit>
python -m pip install -r backend/requirements.txt
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
python -m alembic -c <backend-alembic-configuration> heads
```

前端 `VITE_API_BASE_URL` 必须在构建前确定。同源时使用空串，分域时使用 API origin（例如 `https://api.example.invalid`，不带 `/api` 后缀），因为接口路径已经包含 `/api/v1`。拆分域名时还需验证 CORS、Cookie、图片地址及 WebSocket。私密配置只注入服务端运行环境。

## 发布顺序

1. 在预发布按同版本执行静态检查、浏览器角色旅程、真实数据库检查和恢复演练，确认单一迁移 head。
2. 关闭新注册、发布和下单；若迁移或备份要求冻结写入，停止所有 API、任务、上传、导出和清理写入者，等进行中请求结束。
3. 在同一冻结窗口生成数据库及对象快照，保存迁移版本、数量、引用与哈希，并确认备份可读取。
4. 使用独立迁移账号执行向前迁移，核对版本和约束。迁移失败保留日志并维持暂停，不让新应用接收流量。
5. 启动新应用与唯一或可协调的任务进程，验证秘密注入、存储、数据库、Redis和后台任务，再做只读与合成账号烟测。
6. 发布前端资源，保留旧带哈希资源到缓存窗口结束；确认新旧页面与 API 在切换期间兼容。
7. 按批准范围切换流量、观察指标，再恢复功能开关，记录时间、操作者、版本与验证结果。

```text
pg_dump --format=custom --file <encrypted-backup-staging-file> --dbname <database-name>
python -m alembic -c <backend-alembic-configuration> upgrade head
curl --fail https://<site-domain>/api/v1/health/ready
```

连接参数由受控环境或凭据文件提供。迁移、数据修复和对象迁移必须有事务/批次边界及失败恢复方案，禁止在含真实数据的库中演练降级。

## 兼容与回滚

- 数据结构采用先扩展、后切换、再清理：先增加允许旧应用工作的字段/表，完成双版本兼容和回填后切换读取，另一个发布窗口才删除旧结构。
- 应用回滚：保持当前数据库，只有旧版本兼容该结构时切换回旧产物；否则保持入口暂停，优先修复前进。
- 数据回滚：需要负责人确认数据损失窗口，用事故前一致备份恢复到新隔离数据库与对象位置，核验后再切换。数据库与对象必须成对恢复。
- `alembic downgrade` 仅用于预先验证无数据损失的兼容场景，不能作为默认生产回滚办法。
- 就绪检查或关键旅程失败时不开放流量；保存证据，回到上个兼容版本或执行隔离恢复。

## 静态资源、文件与 WebSocket

带内容哈希的静态资源可长缓存；HTML、权限接口和私密文件不长缓存。前端 SPA 路由回退到 `index.html`，`/api` 和上传接口不能回退为 HTML。控制上传大小与代理超时，并验证错误页面不会掩盖 API 失败。

反向代理支持 WebSocket Upgrade/Connection、合适的空闲超时和心跳；多实例实时通信依赖 Redis 协调，并从 PostgreSQL 补拉消息。重新连接不得复用已消费票据。发布前必须在真实代理链路验证，而不能用本机浏览器成功代替。

上传目录或对象桶在版本间持久保留；原图、缩略图和私有材料禁止被应用重建覆盖。审计导出/清理任务只运行经验证的实例数，发布前核对任务协调与重复执行行为。
