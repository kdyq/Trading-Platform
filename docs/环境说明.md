## 2. 可复现检测命令

在项目根目录使用 PowerShell 执行。

### 基础工具

```powershell
git --version
node --version
npm --version
corepack --version
pnpm --version
python --version
& 'D:\python\virtual\fastapi-env\Scripts\python.exe' --version
```

预期：命令均以退出码 0 完成；固定 Python 环境路径存在。版本允许升级，但升级后必须重新跑完整检查。

### PostgreSQL 与 Redis

```powershell
psql --version
Get-Service -Name 'postgresql-x64-18'
Get-NetTCPConnection -LocalPort 5432 -State Listen
redis-server --version
redis-cli ping
Get-NetTCPConnection -LocalPort 6379 -State Listen
```

预期：PostgreSQL、Redis 服务为 `Running`，两个端口均有本机监听，Redis 返回 `PONG`。

连接数据库时从本地秘密存储取得项目 URL，先执行只读身份核对，再做自动回滚探测；不要在终端输出 URL：

```sql
SELECT current_database(), current_user,
       current_setting('server_encoding'), current_setting('TimeZone');
BEGIN;
CREATE TEMP TABLE codex_connection_probe(id integer);
INSERT INTO codex_connection_probe VALUES (1);
SELECT count(*) FROM codex_connection_probe;
ROLLBACK;
```

预期：数据库名为 `campus_trading_platform`，编码为 `UTF8`，插入计数为 1，事务回滚后探测对象不可见。

### 项目 MCP

```powershell
codex mcp list
```

预期：项目 postgres MCP 为启用状态。通过 MCP 客户端初始化后，`tools/list` 至少包含 `list_schemas` 与 `execute_sql`；调用 `list_schemas` 能看到 `public`，并使用与上节相同的目标库核对和回滚探测确认没有遗留对象。

项目 `.codex/config.toml` 已被 `.git/info/exclude` 排除。检查配置时只确认命令、访问模式、环境变量名与目标数据库名；不得打印连接 URL。

## 3. 依赖策略

- 前端包只在 `frontend` 执行 pnpm 命令，提交 `package.json` 与 `pnpm-lock.yaml`，不提交 `node_modules` 或 `dist`。
- 后端命令固定使用 `D:\python\virtual\fastapi-env\Scripts\python.exe`；缺少依赖时安装到该环境，并维护项目自己的精确依赖清单，不执行整环境 `pip freeze`。
- PostgreSQL、Redis、WSL2 均复用现有安装；Docker 在当前阶段不是前置条件。
- `.env`、数据库 URL、令牌和密码只保存在 Git 忽略的本地文件或进程环境中；`.env.example` 只能包含变量名和非敏感示例。

## 4. 常见故障处理

### 命令存在但版本不符

先记录实际版本并运行项目检查。只有出现可复现的不兼容错误时才升级或降级，不因文档版本号不同就重装整套环境。

### pnpm 不可用

确认 `corepack --version` 成功，再按 `package.json` 的 `packageManager` 字段激活对应 pnpm。所有安装命令必须在 `frontend` 执行。

### 固定 Python 环境不可用

确认 `D:\python\virtual\fastapi-env\Scripts\python.exe` 是否存在。不要新建虚拟环境；先报告真实路径/权限错误，再修复该既有环境。

### PostgreSQL 连接失败

按顺序检查服务、5432 监听、目标数据库名、项目本地配置是否加载，以及 `SELECT current_database()` 的结果。认证失败、参数缺失或用户要求更换时，停止并向用户取得主机、端口、数据库名、用户名和密码；不得猜测或切换到 MySQL/SQLite。

### MCP 失败

先用 `codex mcp list` 检查启用状态，再检查 `uvx`、启动超时和 `DATABASE_URI` 是否由项目配置注入。MCP 是受控开发入口，不替代 Alembic 迁移；结构变更应由迁移文件管理。

### Redis 失败

检查 Redis 服务与 6379 监听。就绪检查可以报告 Redis 不可用，但存活检查不应因此失败；核心业务数据仍以 PostgreSQL 为准。
