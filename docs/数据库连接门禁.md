## 安全复检步骤

1. 从本地秘密存储或 Git 忽略的配置加载连接值，不在命令、日志或文档中打印 URL。
2. 连接后先执行 `SELECT current_database()`；结果不是 `campus_trading_platform` 时立即停止。
3. 核对 `server_encoding=UTF8` 与 `TimeZone=UTC`。
4. 在显式事务中创建探测表、插入一行并回滚；随后用 `to_regclass` 确认对象不存在。
5. 分别通过 psql、asyncpg 与 MCP 执行上述核对，避免把“配置存在”误当作“连接可用”。

建议查询：

```sql
SELECT current_database(), current_user,
       current_setting('server_encoding'), current_setting('TimeZone');

BEGIN;
CREATE TABLE public.connection_rollback_probe(id integer);
INSERT INTO public.connection_rollback_probe VALUES (1);
ROLLBACK;

SELECT to_regclass('public.connection_rollback_probe') IS NULL;
```

探测表名应按运行上下文唯一化，并确保最终检查为 `true`。任何失败都必须先确认目标数据库，再清理可能残留的探测对象。

## 参数失效时的停止条件

遇到以下任一情况时，不猜测、不覆盖配置：

- 项目连接值缺失；
- 认证失败；
- 实际数据库名与目标不符；
- 用户要求更换连接参数。

此时停止后续迁移，并向用户明确取得主机、端口、数据库名、用户名和密码。不得临时切换为 MySQL 或 SQLite。
