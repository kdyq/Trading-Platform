# 拾光集市运维手册

本文说明当前应用的日常运行、暂停、备份与事故处置。上线前由组织方落实真实负责人、替补、联系方式、服务地址、隐私文本、备份位置和保留期限。

## 进程与初始化

API、审计导出 worker、PostgreSQL、Redis 和本地文件目录需要纳入同一运行配置与监控体系。迁移和初始化命令在 `backend` 目录执行：

```powershell
python -m alembic heads
python -m alembic upgrade head
python -m app.db.seed
python -m app.db.bootstrap_super_admin
```

种子用于首次安装角色、权限和默认分类，不作为每次启动步骤。管理员初始化固定创建 `guo`，不创建登录邮箱或虚构校园认证；现有用户名会拒绝覆盖。密码使用无回显提示输入，首次登录必须改密。管理员免校园校验只影响管理权限与账户展示，发布和交易仍需真实有效校园认证。无邮箱账号不能通过邮件找回。

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
python -m app.workers.audit_export
```

这两个命令需要由独立终端或进程管理器持续运行。API 与 worker 必须使用同一有效数据库身份和文件根目录。若配置来源不同，核对非秘密的主机、端口、库名和账号权限，不在输出中打印完整连接串。当前程序使用本地存储，迁移对象桶须完成适配器注入和实际读写验收。

学校、校区和邮箱域名需要先通过受控数据库初始化录入真实目录；当前后台能够维护现有条目，尚无创建目录的界面。工作人员使用各自账号，不能共享超级管理员凭据。

## 后台任务

审计导出 worker 默认每 5 秒轮询，可用 `--interval 10` 调整；`--once` 只处理一次，不能替代常驻进程。任务最后心跳超过 10 分钟会标记失败，操作者可以重新申请；任务一小时后过期。worker 清理撤销或到期的文件，并以有限批次执行隐私清理。

导出目录为私有根目录下的 `exports/`。不得直接挂载到公开文件服务；API 下载会重新检查权限、所有者、期限和撤销状态。只启动 API 而未启动 worker 会使导出停在 `queued`。

API 内运行通知和订单过期任务。临时商品图片清理由调度器定期调用：

```powershell
python -m app.db.cleanup_product_images
```

临时图片默认 24 小时后可清理；详情与异常孤儿处理见 [图片存储策略](商品图片存储策略.md)。

## 功能暂停

修改环境变量后重启所有 API 实例，验证稳定业务错误：

| 开关 | 关闭后的范围 | 错误代码 |
| --- | --- | --- |
| `AUTH_REGISTRATION_ENABLED=false` | 新注册 | `registration_closed` |
| `PUBLISHING_ENABLED=false` | 新建草稿、提交审核、审核通过、管理员直接恢复上架 | `publishing_paused` |
| `TRADING_ENABLED=false` | 新建订单 | `trading_paused` |

开关默认开启，上线时应显式配置。暂停仍允许处理既有订单、撤回与隐藏内容，以及举报申诉。发布暂停期间，申诉成立可以撤销处罚，但被隐藏的原在售商品保持隐藏，待恢复发布后重新确认上架。

普通暂停账户仍可登录、管理本人安全信息、查看通知并提交处罚申诉。业务与后台入口拒绝暂停账户。工作人员停用走专门的工作人员管理流程；举报处罚不能绕过工作人员权限与最后一个超级管理员保护。

疑似权限泄漏、凭据暴露或大面积异常时，暂停入口、限制外部访问、保存请求 ID 和时间范围，升级给安全/隐私负责人。恢复开关时记录操作者、复核者、时间与验证结果。

## 一致备份与恢复

建议目标为 RPO 不超过 24 小时、RTO 不超过 4 小时。目标必须由实际备份调度、独立存储和恢复演练证明，不是当前单机系统的可用性保证。

至少每日备份 PostgreSQL 与匹配的公开、私密对象快照，保存到加密的独立位置。形成一致快照需要冻结全部写入者：停止 API、上传入口、导出和清理 worker、订单过期与通知任务、其他会写数据库或对象的进程；等待进行中的请求退出，确认无写入后依次备份数据库与对象并计算哈希，在完成前保持冻结。关闭三项功能开关不能替代冻结。

连接信息通过受控环境变量或本机凭据文件提供。命令示意：

```text
pg_dump --format=custom --file <备份绝对路径> --dbname <数据库名>
pg_restore --no-owner --no-privileges --dbname <新隔离数据库名> <备份文件>
```

记录 Git 版本、迁移版本、备份起止时间、哈希和核心表数量。文件快照包括公开原图和缩略图、私密申诉/举报材料、导出目录。Redis 中验证码、一次性票据与限流状态可重新生成，不回放旧票据；会话和业务状态以 PostgreSQL 为准。

发生事故先保全原库和文件，恢复到新隔离数据库及对应文件目录。核对迁移版本、数量、图片与私密对象引用、哈希，再执行登录、浏览、订单和后台只读烟测。由事故负责人按已审阅切换步骤恢复服务。不对真实数据直接执行 `alembic downgrade`；应用回滚先验证与当前结构兼容性，不兼容时优先修复前进或从一致快照整体恢复，记录数据损失窗口。

## 日常检查与交接

- 检查存活与就绪探针、API 错误、worker 心跳、队列长度、文件容量和备份结果。
- 留存审计，按规定处理举报与申诉；私密文件只通过授权入口访问。
- 离岗时撤销工作人员角色、会话和受影响密钥，交接待处理任务，不交接明文密码。
- 配置、存储或备份方案变更后，在隔离环境重新验证恢复。
- 质量检查使用根目录 `scripts/check.ps1`；交易、权限或迁移变更额外执行实际 PostgreSQL 与浏览器回归。

## 反馈与试运行退出

反馈记录页面、角色、请求 ID、时间、复现步骤与影响范围，避免收集密码、验证码、私聊全文和认证材料。P0（泄漏、批量越权、不可恢复）立即暂停并升级；P1（关键交易链路阻断）当班升级并评估暂停交易；P2（局部功能或体验）进入修复队列。

出现未解决 P0、无法恢复一致备份、保留要求未落实、关键流程持续失败或值班责任缺位时退出试运行。扩大范围前复核恢复演练、用户反馈、权限与正式隐私文本。详细上线设计见 [部署方案](部署方案.md)、[发布流程](发布流程.md)、[监控与安全运维](监控与安全运维.md) 和 [容量与多校路线](容量与多校路线.md)。
